## 1. 나의 AI 에이전트의 강점

### 🎯 핵심 강점 및 특화 설계
본 AI 에이전트(카오, KAO)는 단순한 키워드 매칭이나 일반적인 LLM 환각(Hallucination) 응답을 지양하고, **실제 이커머스 운영 환경에서 발생하는 복합적인 분쟁, 하자 판정, 보안 및 권한 예외 상황을 규정집과 실제 시스템 API에 기반하여 무결점으로 처리**하도록 설계되었습니다.

1. **규정 거버넌스 3단계 서열 및 권한 위임 체계 엄격 준수**
   - **상담사 재량(1단계)**: 건당 5만 원 이하 명백한 하자 환불, 결제 후 7일 이내 가격 인하 차액 보상 쿠폰(`CARE5000`) 즉결 발급.
   - **운영자 판단(2단계)**: 재량 범위 밖의 정책 예외 및 운영 리스크 1차 검토.
   - **조합장 전결(3단계)**: 5만 원 초과 대형 보상, 안전·법률 분쟁, 신체 피해(배탈·병원비) 및 계속성 선약속(과거 상담사의 과잉 약속 거절) 사안은 즉결 약속을 엄격히 금지하고 정식 에스컬레이션(`POST /api/escalations`, LANE 2)으로 안전하게 인계.

2. **실제 대회 Action API와의 100% 실시간 동적 연동**
   - Mocking 데이터에 의존하지 않고, 대회 공식 서버(`gyodong-mall-action.aitop100.org`)와 실시간 통신하여 배송지 변경(`POST /api/orders/{order_no}/address-change-requests`), 현금영수증 발행, 로트 안전점검 조회, 재배송 접수를 직접 처리합니다.
   - 발화 속 주문번호(`100\d{6}`), 전화번호, 로트번호를 동적으로 추출하여 임의의 주문에 대해서도 유연하게 대응합니다.

3. **물류 및 콜드체인 실물 증빙 기반의 정밀 하자 판정**
   - 수산물 자연감량 허용치(빙장 3%, 합산 8% 이내 정상, 8% 초과 시 부족분 전액 환불/재배송) 정밀 계산.
   - 냉동 수산물 콜드체인(-18℃ 정상, -15℃ 초과 30분 지속 시 공식 해동 이탈 판정) 정본 원칙 준수.
   - 간선 인계 시점의 온도가 정상이더라도 운송 중 해동 이력이 발생한 사고 건(06-24 옥돔 배송 사고 등)을 정확히 인지하고 고객 구제 처리.

4. **카카오톡 공식 플랫폼 규격 완벽 대응**
   - 카카오톡 챗봇 말풍선 규격인 **SimpleText 500자 제한을 100% 엄수**하여 메시지 잘림이나 전송 실패를 원천 차단.

## 2. 정보 획득 접근 방식 (관계자 네트워크 및 정본 해금)

본 프로젝트는 주관적인 추측을 배제하고, 대회 내 10인의 이해관계자(NPC)를 체계적으로 추적·인터뷰하여 공식 1차 자료(정본 문서)를 획득하는 **"조직 네트워크 탐색 접근법"**을 사용했습니다.

1. **소개 계보(Referral Tree) 추적**:
   - `이민준`(청년회 운영·정산)과의 초기 인터뷰를 통해 공식 판매·환불 규정집(25개 조문)과 과거 상담 이력 원장(티켓 4건)을 확보하고, `구방만`, `고길동`, `김청년`, `홍보라` 채널을 1차 해금.
   - `고길동`(조합장)을 통해 환불 산식, 권한위임표 및 **공식 조직 관계도 4페이지 정본**을 확보하고 `박수복`(농산 공급 대표) 채널 해금.
   - `김청년`을 통해 갯마을 위탁 창구인 `홍이장`(이장 겸 조합장)을 소개받고 조업·입고 기록 확보.
   - `홍이장`을 통해 `홍보걸`(인플루언서)과 `박민아`(냉동 배정 기사) 채널을 해금.

2. **공식 실물 증빙 자료 전수 교차 검증**:
   - **홍보걸**: 라이브 방송 스크립트 및 캡처 실물 7종을 입수하여 `SUBAK15` 코드의 조건(15% 할인, 수박 한정, 조합원 할인 5% 중복 불가, 원장 정본 원칙) 확인 (`data/influencer_materials/`).
   - **박민아 기사**: 출하장 업무 인계 대장 및 당일 수첩 메모 실물을 확보하여 06-24 구방만 기사 부재 시 대행 운행 및 냉동장치 고장 해동 이탈 사실 확인 (`data/handover_records/`).
   - **박수복 대표**: 개별 농가 3인(하동철, 문귀남, 최덕만)은 대리 진술 대상이며 대외 창구가 박수복 1인으로 단일화되어 있음을 확인.

## 4. 주요 설계 및 구현 방법

### 🏗️ 시스템 아키텍처

```
[ 카카오톡 사용자 ]
        │ (메시지 발송)
        ▼
[ 카카오톡 봇 API / 오픈빌더 스킬 ]
        │ POST /webhook 또는 /skill/chat
        ▼
[ Cloudflare Tunnel ] (HTTPS 공개 도메인 중계)
        │ Local Proxy
        ▼
[ FastAPI Server (server.py) ]
  ├── 1. 세션 상태 관리자 (User Session Memory / FSM)
  ├── 2. 발화 전처리 및 정규식 동적 파라미터 추출기
  ├── 3. 규정 기반 비즈니스 로직 & 권한 라우터
  ├── 4. 정본 지식 베이스 질의응답 엔진 (knowledge_base.py)
  ├── 5. 대회 Action API 클라이언트 (HTTP Bearer 인증)
  └── 6. 비동기 메시지 콜백 워커 (BackgroundTasks)
```

1. **하이브리드 카카오 웹훅 처리기 (`server.py`)**:
   - **신규 카카오톡 봇 API**: 1초 이내에 `200 OK`를 먼저 반환하고, 백그라운드 태스크에서 비즈니스 로직 및 Action API를 처리한 후 카카오 메시지 콜백 API(`POST https://kapi.kakao.com/v1/bot/callback`)로 응답 전송.
   - **기존 카카오 i 오픈빌더**: 동기식 `SkillResponse` 포맷으로 즉시 반환.
2. **정본 지식 베이스 질의응답 엔진 (`knowledge_base.py`)**:
   - 조직 관계도 4페이지, 1차 인터뷰 원문, 판매·환불 규정 25개 조문, 물류 인계 대장, 기사 수첩 메모, 조업 일지 등 수집한 모든 정본 데이터를 구조화하여 탑재.
   - 인물 10인 및 농가 3인의 역할/연락처/대리 관계, 06-24 물류 사고 원인, 06-30 금어기 품절 사유, 25개 환불 규정 및 거버넌스 승인 서열 질문 등에 대해 지연 0ms로 정본에 입각한 500자 이하의 완벽한 답변을 제공.
3. **FSM 기반 다단계 대화 세션 관리**:
   - 배송지 변경(1단계: 주문 확인 및 집하 상태 조회 ➡️ 2단계: 상세 주소 입력 접수)과 같이 여러 턴에 걸쳐 진행되는 시나리오를 사용자 키(`user_id`) 기반 세션 메모리로 안정적으로 추적.
4. **인프라 자가 치유(Self-healing) 터널링**:
   - `server.py` 기동 시 별도 데몬 스레드로 `cloudflared` 터널 프로세스를 구동하고, 프로세스 비정상 종료 시 자동 재시작 및 공인 웹훅 URL 실시간 로깅.

## 5. 아쉬웠던 점 및 한계점

1. **대회 초반 신규 카카오톡 봇 API 규격 파악 지연**:
   - 기존 카카오 i 오픈빌더의 동기식 응답(5초 타임아웃) 방식에 익숙해져 있어, 신규 봇 API의 웹훅 이벤트(`callbackToken` 수신 후 1초 내 응답 + 비동기 콜백 발송) 구조를 사전에 면밀히 파악하지 못해 초반 플랫폼 연동에 일부 시간을 소모했던 점이 아쉬웠습니다.
2. **관계자 발굴 초기의 유추 시행착오**:
   - 초반 조직 관계도 정본을 확보하기 전, 농가 3인(하동철, 문귀남, 최덕만)이 독립적인 소통 채널을 보유하고 있을 것으로 임의 유추하여 시간을 지체했으나, 고길동 조합장으로부터 4페이지 정본 조직도를 확보한 뒤 공급자 대표(박수복) 1인 단일 창구 규칙을 확인하고 오류를 바로잡을 수 있었습니다.
3. **향후 발전 방향**:
   - 향후 외부 생성형 LLM(RAG)을 백엔드에 결합할 경우 더욱 다채로운 문체와 유연한 대화가 가능해질 것이며, 현재 구축한 정본 지식 베이스를 벡터 DB 및 검색 엔진으로 확장할 수 있습니다.
