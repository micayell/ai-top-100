# 교동마을 산지직송 AI 고객센터 챗봇 카오(KAO)

> **구분**: AI Top 100 예선 프로젝트 및 기술 포트폴리오  
> **작성자**: 김창주  
> **프로젝트 개요**: 규정 거버넌스와 정본 지식 베이스, 실시간 커머스 Action API를 결합한 카카오톡 기반 이커머스 고객상담 AI 에이전트

---

## 1. 프로젝트 소개 및 핵심 강점

본 프로젝트는 단순한 키워드 매칭이나 일반적인 LLM의 환각(Hallucination) 응답을 배제하고, **실제 이커머스 운영 환경에서 발생하는 복합적인 분쟁, 신선식품 하자 판정, 보안 및 권한 예외 상황을 공식 규정집과 실시간 시스템 API에 기반하여 정확하게 처리**하도록 설계된 AI 고객센터 에이전트입니다.

1. **규정 거버넌스 3단계 서열 및 권한 위임 체계 준수**
   - **상담사 재량(1단계)**: 건당 5만 원 이하의 명백한 하자 환불, 결제 후 7일 이내 가격 인하 차액 보상 쿠폰(`CARE5000`) 즉결 발급.
   - **운영자 판단(2단계)**: 상담사 재량 범위를 벗어나는 정책 예외 및 운영 리스크 1차 검토.
   - **조합장 전결(3단계)**: 5만 원 초과 대형 보상, 안전·법률 분쟁, 신체 피해(배탈·병원비) 및 계속성 선약속(과거 상담사의 과잉 약속 거절) 사안은 임의 약속을 금지하고 정식 에스컬레이션(`POST /api/escalations`, LANE 2)으로 인계.

2. **실시간 커머스 Action API 및 동적 OpenAPI 스키마 연동**
   - 정적 Mocking 데이터에 의존하지 않고, OpenAPI 명세(`data/actions.json`)를 동적으로 파싱하여 대회 공식 Action API 서버(`gyodong-mall-action.aitop100.org`)와 실시간 통신합니다.
   - 회원 및 주문 조회, 배송지 변경(`POST /api/orders/{order_no}/address-change-requests`), 현금영수증 발행, 로트 안전점검 조회, 재배송 및 환불 접수, 에스컬레이션 등록을 에이전트가 스스로 판단하여 실행합니다.

3. **물류 및 콜드체인 실물 증빙 기반의 정밀 하자 판정**
   - 수산물 자연감량 허용치(빙장 3%, 합산 8% 이내 정상, 8% 초과 시 부족분 전액 환불 또는 재배송) 정밀 계산.
   - 냉동 수산물 콜드체인(-18℃ 정상, -15℃ 초과 30분 지속 시 공식 해동 이탈 판정) 정본 원칙 적용.
   - 간선 인계 시점의 온도가 정상이더라도 운송 중 해동 이력이 발생한 사고 건(06-24 옥돔 배송 사고 등)을 교차 검증하여 고객 구제 처리.

4. **멀티모달 입력 처리 및 카카오톡 플랫폼 규격 대응**
   - 고객이 전송한 파손 사진(JPG, PNG, GIF, WebP)이나 음성 파일(M4A, MP3, WAV, OGG) URL을 실시간 다운로드 및 인코딩하여 멀티모달 컨텍스트로 분석합니다.
   - 카카오톡 챗봇 말풍선 규격인 SimpleText 글자 수 제한(500자 이내)을 엄수하여 메시지 잘림이나 전송 실패를 방지합니다.

## 3. 시스템 아키텍처 및 주요 구현 방법

### 3.1 전체 시스템 구조

```text
[ 카카오톡 사용자 ]
        │ (텍스트 / 이미지 / 음성 메시지 발송)
        ▼
[ 카카오톡 봇 API / 오픈빌더 스킬 ]
        │ POST /webhook 또는 POST /skill/chat
        ▼
[ Cloudflare Tunnel ] (HTTPS 공개 도메인 중계)
        │ Local Proxy (http://127.0.0.1:8000)
        ▼
[ FastAPI 통합 서버 (server.py) ]
  ├── 1. 세션 상태 관리자 (User Session Memory / RLock 기반 스레드 안전 멀티턴 관리)
  ├── 2. 메타데이터 파서 및 멀티메시지 버스트 디바운서 (Debouncer)
  ├── 3. 비동기 메시지 콜백 워커 (Background Thread -> Kakao Bot Callback API)
  └── 4. 데이터 기반 AI 에이전트 루프 (knowledge_base.py)
          ├── 정본 지식 베이스 로더 (HTML/TXT/MD 정제 및 통합 컨텍스트 구축)
          ├── OpenAPI 명세 동적 파서 (actions.json -> API 호출 규격 추출)
          ├── 멀티모달 미디어 페처 (이미지/오디오 Base64 inlineData 변환)
          ├── 2-Pass ReAct 추론 루프 (1차 조회 API 실행 -> 2차 후속 조치 및 최종 답변 생성)
          └── 대회 공식 Action API 클라이언트 (HTTP Bearer 인증 통신)
```

### 3.2 핵심 모듈별 설계 상세

1. **하이브리드 카카오 웹훅 처리기 및 디바운싱 (`server.py`)**
   - **신규 카카오톡 봇 API 대응**: 웹훅 수신 시 1초 이내에 `200 OK`를 즉시 반환하고, 데몬 스레드에서 에이전트 추론 및 Action API 호출을 수행한 뒤 카카오 메시지 콜백 API(`POST https://kapi.kakao.com/v1/bot/callback`)로 최종 응답을 전송합니다.
   - **기존 카카오 i 오픈빌더 호환**: `callbackToken` 유무를 자동 판별하여 동기식 `SkillResponse` v2.0 포맷도 단일 엔드포인트에서 동시에 지원합니다.
   - **멀티메시지 버스트 디바운싱 및 동시성 제어**: 평가 환경이나 실제 상담에서 메타데이터, 첨부 미디어 URL, 본문 발화가 연속으로 유입될 때 세션별 재진입 락(`RLock`)과 시퀀스 번호(`msg_seq`)를 추적하여 중복 응답과 경합 조건(Race Condition)을 방지합니다.

2. **정본 지식 베이스 및 동적 OpenAPI 에이전트 (`knowledge_base.py`)**
   - 서버 기동 시 판매·환불 규정 25개 조문, 상품 카탈로그, 상담 이력 원장, 조직 관계도, 기상 운영 기준, 조업·입고 기록, 부분환불 산식표, 인플루언서 방송 기록, 관계자 인터뷰 전문을 정제하여 통합 컨텍스트로 적재합니다.
   - `data/actions.json` OpenAPI 스키마에서 엔드포인트 경로, 쿼리 파라미터, 필수 요청 바디 필드 및 Enum 제약 조건을 동적으로 추출하여 프롬프트에 주입합니다.
   - **2-Pass Action 실행 루프**: 1차 패스에서 필요한 조회성 API(`GET`)를 먼저 호출하여 결과를 세션 로그에 누적하고, 2차 패스에서 조회된 실데이터를 바탕으로 상태 변경 API(`POST`) 실행 및 수치·접수번호가 반영된 최종 답변을 생성합니다.

3. **인프라 자가 치유(Self-healing) 터널링 (`server.py`)**
   - 서버 기동 시 기존에 실행 중인 `cloudflared` 프로세스와 `tunnel_url.txt`를 확인하여 웹훅 도메인이 불필요하게 변경되는 것을 방지하고, `cloudflared` 바이너리가 없는 환경에서는 에러 없이 로컬 서버 모드로 안전하게 기동합니다.

## 4. 도메인 정보 획득 및 정본 데이터 구축 과정

주관적인 추측을 배제하고, 대회 내 이해관계자(NPC) 네트워크를 체계적으로 탐색·인터뷰하여 공식 1차 자료(정본 문서)를 확보하고 교차 검증했습니다.

1. **소개 계보(Referral Tree) 기반 관계자 탐색**
   - `이민준`(청년회 운영·정산): 공식 판매·환불 규정집(25개 조문)과 과거 상담 이력 원장(티켓 4건) 확보, `구방만`, `고길동`, `김청년`, `홍보라` 채널 해금.
   - `고길동`(조합장): 부분환불 산식표, 권한위임표 및 공식 조직 관계도 4페이지 정본 확보, `박수복`(농산 공급 대표) 채널 해금.
   - `김청년`(체험·행사 총괄): 우천 취소 기준 확인 및 갯마을 위탁 창구인 `홍이장`(이장 겸 조합장) 소개를 통한 조업·입고 기록 확보.
   - `홍이장`: `홍보걸`(인플루언서)과 `박민아`(냉동 배정 기사) 채널 해금.

2. **실물 증빙 자료 교차 검증**
   - **홍보걸**: 라이브 방송 스크립트 및 캡처 실물 7종을 대조하여 `SUBAK15` 프로모션 코드 조건(15% 할인, 수박 한정, 조합원 할인 5% 중복 불가, 원장 정본 우선 원칙) 검증.
   - **박민아 기사**: 출하장 업무 인계 대장 및 당일 수첩 메모 실물을 대조하여 06-24 구방만 기사 부재 시 대행 운행 및 냉동장치 고장으로 인한 해동 이탈 사실 확인.
   - **박수복 대표**: 개별 농가 3인(하동철, 문귀남, 최덕만)은 대리 진술 대상이며 대외 창구가 박수복 대표 1인으로 단일화되어 있음을 확인.

## 5. 검증 방식 (Validation & Testing)

안정적인 챗봇 서비스를 보장하기 위해 3단계 검증 체계를 적용했습니다.

1. **시나리오 단위 및 멀티턴 통합 검증**
   - 15개 주요 상담 테스트 케이스(L-03, L-05, L-11, L-20, L-23, L-32, L-33, L-34, L-40, L-47, L-60, R-05-a, Y-07-b, Y-16, Y-24)의 입력 발화 및 다단계(Multi-turn) 대화 흐름을 시뮬레이션하여 규정 준수 여부와 Action API 호출 파라미터를 검증했습니다.
2. **실시간 Action API 연동 검증**
   - 대회 공식 Action API 서버로 실제 HTTP `GET`/`POST` 요청을 전송하여 상태 코드(`200`, `201`) 및 응답 데이터를 확인하고, 중복 호출 방지 로직을 검증했습니다.
3. **정적 코드 분석 (Static Analysis & Linting)**
   - IDE 코드 인스펙션을 통해 타입 어노테이션, 예외 처리, 인코딩 안전성을 점검하여 **0 warnings / 0 errors** 상태를 유지했습니다.

## 6. 프로젝트 디렉토리 구조 및 실행 안내

```text
ai-top-100/
├── server.py           # FastAPI 통합 웹훅/스킬 서버, 세션 관리, 비동기 콜백 및 터널 데몬
├── knowledge_base.py   # 정본 지식 베이스 동적 로더, 멀티모달 처리 및 2-Pass Action 에이전트
├── requirements.txt    # 파이썬 패키지 의존성 명세
├── .env.example        # 환경 변수 설정 예시 파일
├── PLAN.md             # 프로젝트 진행 계획 및 도메인 퀘스트 추적 문서
├── README.md           # 프로젝트 포트폴리오 및 기술 문서
└── .gitignore          # 외부 데이터(data/), 실행 파일(cloudflared.exe), 환경변수(.env) 제외 설정
```

> **참고 사항**: 대회에서 제공된 원본 데이터(`data/` 디렉토리 내 HTML, PDF, XLSX, 이미지, OpenAPI 명세 등)와 외부 바이너리(`cloudflared.exe`), 실제 API 인증 키(`.env`)는 저작권 및 보안 정책에 따라 `.gitignore`에 등록되어 공개 저장소에는 포함되지 않습니다.

### 실행 방법

1. `.env.example` 파일을 복사하여 `.env` 파일을 생성하고 인증 키를 입력합니다.
   ```bash
   cp .env.example .env
   ```
2. 필수 패키지를 설치하고 서버를 구동합니다.
   ```bash
   pip install -r requirements.txt
   python server.py
   ```

## 7. 회고 및 향후 개선 방향

1. **비동기 웹훅 규격 대응 경험**
   - 초기에는 카카오 i 오픈빌더의 동기식 응답(5초 타임아웃) 구조를 기준으로 접근했으나, 신규 카카오톡 봇 API의 비동기 웹훅(`callbackToken` 수신 후 1초 내 응답 및 백그라운드 콜백 전송) 규격을 분석하여 두 방식을 모두 처리할 수 있는 통합 핸들러로 개선했습니다.
2. **도메인 정본 확보를 통한 환각 제어**
   - 초기 탐색 단계에서 개별 농가 3인이 독립 채널을 보유했을 가능성을 열어두었으나, 4페이지 정본 조직도를 확보한 후 공급자 대표(박수복) 단일 창구 규칙을 확인하여 근거 없는 추측성 응답을 차단할 수 있었습니다.
3. **향후 발전 방향**
   - 현재는 전체 정본 문서를 정제하여 LLM 컨텍스트에 직접 주입하는 방식을 사용하며, 향후 문서 규모가 대규모로 확장될 경우 문서 청킹(Chunking) 및 하이브리드 검색(Vector + BM25) 파이프라인으로 고도화할 수 있습니다.
